<h3 id="cn-v0.4.1">🐛 修复 — 手机上聊天区滑不动</h3>

手机端 DSH 外壳在窄屏下的根层 `pI_x6G_frame` 是 `overflow:hidden` 且内容溢出（实测 `clientHeight=844 / scrollHeight=1688`），同时整页不可滚，于是内容被裁住、手指滑不动。桌面 Chrome 同视口正常，属 iOS/窄屏布局差异，与反向代理无关。

新增默认开启的 `mobileScrollFix`：只在「窄屏 + 移动 UA + 整页不可滚 + 找到被裁剪溢出的层」四条同时成立时，把那些层改成可触摸滚动；正常页面一律不碰。页面加 `?lgdiag=1` 可看一屏布局诊断。

`mobileCompat` 与 `socketWatchdog` 保持关闭（0.4.0 曾导致手机整页空白，先不再默认开启）；代答心跳 `answerHeartbeat` 保持开启。

<h3 id="en-v0.4.1">🐛 Fixed — the chat column could not be scrolled on a phone</h3>

DSH's own shell clips the conversation column on narrow screens: the root layer `pI_x6G_frame` is `overflow:hidden` while its content overflows (measured `clientHeight=844 / scrollHeight=1688`), and the page as a whole cannot scroll either. Desktop Chrome on the same viewport scrolls fine, so this is an iOS/narrow-screen layout difference, not the reverse proxy.

New switch `mobileScrollFix` (on by default): the injected script only acts when narrow screen AND mobile UA AND the page cannot scroll AND it finds a layer that clips overflowing content; it then makes exactly those layers touch-scrollable. Healthy pages are never touched. `?lgdiag=1` prints an on-screen layout report.

`mobileCompat` and `socketWatchdog` stay off (0.4.0 blanked the page on phones); `answerHeartbeat` stays on.
