dsh-lan-guard `0.4.2` · 已验证 DeepSeek Harness `0.1.7-rc.2`

<h3 id="cn-v0.4.2">🐛 修复 — 手机上缺少「回到底部」按钮</h3>

官方自带该按钮，显示条件是「不在尾部」，而该判断基于官方认定的滚动层；窄屏下实际滚动发生在官方布局的 `pI_x6G_frame`，conversation 的 `[data-conversation-scroll]` 内容高度没有跟着涨（实测 `convScroll 754/754` vs `pI_x6G_frame 844/1688`），于是官方永远以为还在尾部、按钮不出现。

网关侧补一个（并入 `mobileScrollFix`）：找出当前真正在滚动的容器，不在尾部时显示 36px 圆形浮动按钮，点击平滑到底；官方按钮一旦出现就自动让位；按钮位置按输入框动态计算，不会压住输入区。

<h3>同时修复 — 打开左侧边栏被遮罩盖住</h3>

滚动矫正给内容层加的 `overflow-y:auto !important`（以及 `-webkit-overflow-scrolling:touch`）会与官方抽屉打开时的滚动锁定/层级打架，表现为侧边栏被灰雾盖住、点不动（用户 A/B 实测确认）。现在：检测到全屏遮罩/对话框时**完全撤销**自己的样式并隐藏按钮；去掉 `-webkit-overflow-scrolling`（iOS 强制合成层，正是层级错乱来源）。

<h3>升级</h3>

```sh
dsh plugin --profile web add dsh-lan-guard@latest
```

重启一次 dsh 生效。

<h3 id="en-v0.4.2">🐛 Fixed — the "back to bottom" button was missing on a phone</h3>

The official button exists, but it shows only when `!followingTail`, judged against the scroll layer the official code believes in. On narrow screens the actual scrolling happens in the layout layer `pI_x6G_frame`, while conversation's `[data-conversation-scroll]` never grows (`convScroll 754/754` vs `pI_x6G_frame 844/1688`), so the official code always thinks it is at the tail and the button never appears.

This release adds one at the gateway layer (inside `mobileScrollFix`): it finds the container that is really scrolling, shows a 36px floating button whenever the view is not at the bottom, and smooth-scrolls to the end on click. It yields to the official button as soon as that one appears, and positions itself above the composer dynamically.
