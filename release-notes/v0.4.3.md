<h3 id="cn-v0.4.3">🔧 方向修正 — 用「高度链」而不是 overflow 补丁</h3>

对照实验（用户实测）：3080 直连能拖动、3081 经代理拖不动；而 dsh-mobile 在同一套官方 UI 与同一台手机上可用——它的做法是移动端高度链：`html,body,#root{height:100%;overflow:hidden}` + shell `100dvh` + 主区 `min-height:0`。

根因：官方外壳在窄屏 iOS 下高度链断裂（实测内容 1688 被裁在 844 的层里，官方认定的滚动层 `[data-conversation-scroll]` 永远 754/754）。所以打开会话不会停在最新、手指拖不动、官方「回到底部」点了没反应。

现在 `mobileScrollFix`：给根一个确定高度（100%/100dvh）+ 沿被裁层给链上 flex/grid 容器补 `min-height:0`，然后**验证官方滚动层是否真的能滚**——不能就**全部撤销**，页面保持与官方逐字节一致。同时**移除**自建「回到底部」按钮与所有 `overflow-y`/`-webkit-overflow-scrolling` 补丁（官方按钮与"打开即最新"随之恢复）。

<h3>升级</h3>

```sh
dsh plugin --profile web add dsh-lan-guard@latest
```

重启一次 dsh 生效。

<h3 id="en-v0.4.3">🔧 Direction change — fix the height chain instead of patching overflow</h3>

Controlled test (user): the page works on 3080 directly but not through 3081; dsh-mobile works on the same official UI and the same phone, and its approach is a mobile height chain: `html,body,#root{height:100%;overflow:hidden}` + shell `100dvh` + main `min-height:0`.

Root cause: on narrow iOS the official shell's height chain is broken (content 1688 clipped inside an 844 layer; the layer conversation believes in, `[data-conversation-scroll]`, stays 754/754), so a session does not open at the newest message, dragging does nothing, and the official "back to bottom" button has no effect.

`mobileScrollFix` now gives the root a definite height (100%/100dvh), adds `min-height:0` to every flex/grid container on the clipping chain, then VERIFIES that the official scroll layer really scrolls — if not, everything is reverted and the page stays byte-identical to stock. The self-made button and every `overflow-y`/`-webkit-overflow-scrolling` patch are removed.
